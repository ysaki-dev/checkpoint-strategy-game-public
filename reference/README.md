# 式で作るAI — 公開リファレンス v1

## 使い方

ゲームの「式でAIを作る・持ち寄り対戦」を開く。A/Bを選び、Advancedの名前・評価式・parameters・任意の切替条件を入力して「検証してこのAIに適用」。共有テキストをコピーし、相手は同じ画面に貼って「読み込む」。ファイルは不要。

初心者スライダーは例の式を調整する任意の補助で、独自の式に必須の重みではない。適用ボタンを押すまでAdvancedを上書きしない。パラメータの名前・数・重みは自分で決められる（最大32個、各±10000）。適用済みのA/BはこのタブのsessionStorageへ保存する。保存できないブラウザではコピーで保管する。

「自分 vs AI B」は人間と作成したB、「AI A vs AI B」は両方の式で自動対戦する。通常の「AIと練習」は従来の内蔵AIで、式を作っても勝手に置き換わらない。試合中に式を変更しない。

## テキスト形式

```json
{
  "version": 1,
  "name": "得点効率",
  "formula": "if(is_cp, gain / (1 + my_eta + wait) - avoid * occupied + 2 * capturing, -1)",
  "parameters": {"avoid": 3},
  "switchWhen": ""
}
```

構文とパラメータ名を検証する。構文が正しくても、特定の状態で0除算等が起きる式はあり得る。その候補を除外して診断を表示し、全候補が無効なら停止する。検証成功は強さや全状態での成功を保証しない。

## 行動と判断

CP、公開の丘陵中心、現在位置での待機が候補。評価式の最大値を選び、共通の4近傍経路探索で移動する。同点はCP番号、丘陵番号、待機の順。到達不能な候補は除外するが、閉鎖中や冷却中でも待機・フェイントのため向かうことはできる。

ゲーム判定20Hz、判断0.75秒。切替条件が空なら毎判断周期で再評価。条件式は現在の目的地を対象に評価し、0なら維持、0以外なら再評価。初回・増水時等の経路再計画では必要に応じて評価する。目標を維持する秒数に上限はないが、式は規定演算数内でなければならない。

例：`target_age > 3 || occupied` は3秒維持したか、相手に先着されていたら再評価する条件。条件と時間を使ったフェイントは設計できるが、相手が必ず反応する保証はない。

## 特徴量

| 名前 | 値 |
|---|---|
| gain | 到着・待機・取得5秒後に取得可能な場合の見込み点。公開ルールと自分の秘密対象から計算。現在得点ではない |
| cp_id | CPの0始まり番号。丘陵・待機は-1 |
| my_distance | 候補への直線距離（タイル） |
| my_eta | BFS経路のタイル数と道路倍率による推定秒数。最短時間経路を保証しない |
| wait | 到着後、開放・冷却終了までの待機見込み秒数 |
| enemy_known | 相手を直近4秒以内に観察したなら1。不明なら0 |
| enemy_distance / enemy_eta | 最終視認位置からの直線距離 / 基本速度による推定秒数。不明なら0 |
| enemy_heading | 最後に観察した速度方向と候補への方向の一致度（-1〜1）。不明・停止なら0 |
| arrival_advantage | clamp((enemy_eta-my_eta)/10,-1,1)。不明なら0 |
| turn_rate | 観察した移動方向の大きな変化の割合（0〜1）。試合全体の集計で、心理的なフェイント率ではない |
| occupied | 観測上、相手がそのCPの取得優先権を持つなら1 |
| capturing | 自分がそのCPの取得優先権を持つなら1 |
| capture_progress | 観測可能な取得進捗（0〜1）。隠れている相手の進捗は0 |
| is_secret | 自分が選んだ秘密CPなら1 |
| is_cp / is_hill / is_wait | 候補の種類。該当するものだけ1 |
| same_target | 今の目標なら1 |
| target_age | 今の目標を維持している秒数 |
| time / remaining | 経過秒 / 残り秒 |

秘密戦の現在得点や真の相手位置は特徴量へ入れない。最終視認は正当な記憶であり、見失った後の真の移動を追跡しない。高度な式はenemy_knownで推定の不明と0秒を区別する。到着・行動予測は誤り得る。

## 数式言語と制限

四則演算 `+ - * /`、比較 `< <= > >= == !=`、論理 `&& || !`、括弧。比較結果は1/0。

関数：`min(a,b)`, `max(a,b)`, `abs(a)`, `clamp(x,lo,hi)`, `if(condition,a,b)`。ifと論理演算は必要な枝だけ評価する。

テキスト最大32000文字、式4000文字、1024トークン、512構文ノード、24段の入れ子、判断全体8192評価。定数±100万、パラメータ±10000、計算結果の絶対値1e12以内。JSのeval/Function、文字列処理、プロパティ参照、ループ、外部通信は提供しない。

## 公開コード

このreferenceディレクトリには、ルール理解と方策作成に必要なソースを選んで掲載する。

- core/config.ts：時間・速度・視界・得点。
- core/map.ts：地形・予定・開放判定。
- core/game.ts：ゲーム判定と受信者別の情報投影。
- core/visibility.ts / core/secrets.ts：視界、秘密選択の補助。
- core/bot.ts：従来の内蔵AI（作成した方策とは別）。
- policy/expression.ts：数式の構文・評価・制限。
- policy/policy.ts：テキスト形式、特徴量、候補評価と移動制御。

各ファイルのSHA-256をmanifest.jsonに記録する。開発元のGit履歴、サーバー、認証情報、未公開の実験ファイルはコピーしない。ブラウザ内のローカル対戦なので、ページを改変した人からの不正対戦結果を防ぐ審判ではない。

## ニューラルネットとの差

今回の式は、人が意味を決めた特徴量を任意の演算と重みで組み合わせる。ニューラルネットは多数のノードと層を通す数値計算で、学習によって中間表現を獲得できるが、重み1個の意味は通常読み取りにくい。

式の重みを人が設定しただけでは機械学習ではない。対戦結果から重みを探索して改善することはできるが、現在この機能に自動学習・ニューラルモデルのインポート・強化学習は実装していない。

現在、秘密戦のAI秘密CPはゲーム側の既定の独立選択を使う。式から準備中の選択操作を返す機能、自由な内部状態の更新、移動ベクトルの直接出力、ニューラルモデルの読み込みは未実装。
